Sponsor Shield privacy policy

Prepared for version 1.5.0 · 1 October 2026

Sponsor Shield mutes and blurs community-marked sponsor segments on regular YouTube watch pages. This policy explains the data the extension uses to do that.

What stays on your device

The extension reads the current YouTube video ID and player state, including playback position, duration, mute state and whether the player reports an ad. It uses these locally to find matching segments, apply the shield and show status. It does not read your general browsing history, record the video or audio, or capture your screen.

Chrome’s local extension storage holds your on/off preference, self-promotion preference and a running total of sponsor playback time shielded on this device. These values are not sent to the developer or SponsorBlock, and the extension does not use Chrome storage sync. An old installation may retain an unused legacy playback-mode preference.

Segment choices such as Show anyway are held in page memory until navigation to another video or a reload. A service-worker memory cache holds data for at most 48 videos, with a ten-minute reuse limit. It disappears when Chrome stops the worker. It is not a saved watch-history log.

What is sent to SponsorBlock

To look up segments, the extension computes a SHA-256 hash of the video ID locally and sends only its first four hexadecimal characters to https://sponsor.ajay.app/api/skipSegments/<prefix>. The request also includes fixed category and action-type filters. The complete video ID and page URL are not sent by the extension. Matching the response to the complete video ID happens locally.

As with other internet requests, SponsorBlock and its network providers can see your IP address, request timing and ordinary HTTP connection information. An IP address can indicate an approximate location. A short hash prefix reduces disclosure; it does not guarantee anonymity. Sponsor Shield does not use a location API.

Lookups occur when an enabled watch page needs data. While playback is active in a visible tab, the extension normally checks again about every three minutes. A first empty result can cause an earlier recheck after about a minute. Errors delay further requests. Turning the shield off stops new lookups, though a request already in progress can finish.

Requests use HTTPS and omit credentials. Sponsor Shield sends no account details, cookies, playback positions, votes, submissions, viewing reports, preference values or shielded-time totals to SponsorBlock. SponsorBlock is a separate service; its own privacy practices govern its server logs and retention. This extension cannot delete or set a retention period for those logs.

Data use and sharing

The extension has no developer-operated collection server and no analytics, advertising or telemetry SDK. It does not sell user data. Data is used only to provide the described sponsor shielding, settings, status and local time total. The only automatic external data request made by the extension is the SponsorBlock segment lookup described above.

Sponsor Shield’s use and transfer of user data follows the Chrome Web Store User Data Policy, including its Limited Use requirements. Data is not used for advertising, unrelated profiling, creditworthiness or lending decisions. No remote code is downloaded or executed: SponsorBlock responses are parsed as data.

Permissions

  • storage saves local settings and the shielded-time total.
  • activeTab is retained for access associated with opening the popup on the current tab.
  • scripting inserts packaged scripts and styles into already-open supported tabs after installation or an update.
  • Access to youtube.com and www.youtube.com lets the extension find and change the player on supported watch pages, including navigation within the site.
  • Access to sponsor.ajay.app permits segment lookups.

Your controls and deletion

You can turn shielding off, opt in or out of self-promotion shielding, or choose Show anyway for a segment. Chrome’s extension settings let you restrict site access or disable the extension. Removing the extension from Chrome removes its local extension storage; reinstalling starts with the default settings. The extension does not provide a separate reset-total button. Ordinary operating-system or browser-profile backups are outside its control.
